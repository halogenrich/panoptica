# PANOPTICA user guide

PANOPTICA keeps the lab's fabrication procedures as reusable presets, assembles them into device stacks, and records what happened in each batch.

## How the pieces fit

1. **Designs** describe hardware: a *substrate* (glass size and ITO pattern) and a *metal mask* drawn for that substrate.
2. **Recipes** describe one process step: substrate prep, solution, spin coating, organic evaporation, metal evaporation.
3. A **stack** lists the layers of a device, each pointing to its recipes.
4. A **batch** is one fabrication run of a stack. It keeps a frozen copy of the stack and its recipes, its bookings, notes and the run data.

The side menu follows the same order: **Fabrication** (stacks, batches, calendar), **Measurements**, **Recipes**, **Designs**, and **Lab** (inventory, equipment) at the bottom.

A new install has no lab content: no equipment, recipes, designs, tags or example data. Recipes, designs and the inventory start empty, so each lab enters its own. Substances come from the containers: the first container of PbI2 added or imported makes the substance PbI2; give it a formula and a molar mass under Inventory › Substances and the solution calculator can use it.

Typical order: make the substrate and mask designs once; make or reuse recipes; build the stack; start a batch from the stack; print the sheet; enter run data afterwards.

## Library screens

Every design, recipe and stack page has the same layout:

- **All / Mine / Shared** filters the cards; the search box matches names and summaries.
- **New …** opens an empty editor. Click a card to open it.
- An open preset has three tabs: **Recipe** (the computed output), **Run data** (entries from real runs) and **History** (versions).
- **Edit** shows inputs on the left and the live output on the right. On a phone, switch between **Inputs** and **Output**.
- Saving needs a name. If the name at the top is still empty, the button reads **Name and save** and asks for the name in a small box; Enter saves.
- **Duplicate** copies a preset under your name. **Private** presets are visible only to you; **Shared** presets are visible to everyone (only the owner edits them).

### Versions

A preset that is used by a stack, a batch or another preset is never changed in place. Saving it creates *Name v2*, linked to the original, and the original stays as it was, so old stacks and batches keep pointing to what was actually used. Saving someone else's shared preset also creates your own version. Unused presets you own are edited in place. **History** shows the family tree and what changed between versions. A preset in use cannot be deleted.

## Designs

### Substrates

Set the glass size, then draw the ITO with rectangles, parallelograms, trapezoids or free quadrilaterals. *Repeat as array* copies a shape in rows and columns. Shapes can be dragged on the canvas or typed in the table (mm). Also recorded: sheet resistance, ITO thickness, supplier and an orientation mark. The output shows ITO area and strip resistance (R = R<sub>s</sub>·L/W).

Canvas: scroll to zoom, drag the background to pan, **Ctrl Z** / **Ctrl Y** undo and redo, **Ctrl D** duplicates the selected shape.

### Metal masks

A wizard in five steps:

1. **Substrate**: pick the substrate design the mask is made for.
2. **Active areas**: draw the pixels (metal meant to sit over the full stack). **Confirm array as … separate pixels** turns a repeated shape into one shape per pixel. Pixels are numbered P1, P2… in the order of the list (array copies row by row); drag a pixel by its handle (⋮⋮) to reorder, so that the numbers match the pixel numbers of the J–V system (for example 4, 5, 3, 6, 2, 7, 1, 8 from top to bottom). The measurement cells always use the newest pixel order of the mask, also for batches started before the reordering (as long as the pixels themselves were not moved). The canvas shows the numbers as you go.
3. **Connections**: strips from each pixel to a pad on ITO-free glass, and the counter electrode.
4. **Scrape area**: where the layers are scraped off to expose ITO. A suggestion under the counter electrode is offered.
5. **Review and export**.

The live check computes the device area of each pixel (metal over unscraped ITO), parasitic area from strips over ITO (**Accept the recalculated area**: unchecked, recipes and sheets use the drawn pixel area instead), and warns about shorts (pixel metal reaching exposed ITO), pads on ITO, a missing counter electrode, islands that a mask cannot hold, openings or bridges thinner than the minimum feature, and openings beyond the glass.

Exports, for the **aperture** (active areas), **evaporation** (all metal) and **scrape stencil** masks: **STL** (plate with holes, optional substrate pocket; open in Tinkercad or a slicer), **SVG** and **DXF** (outlines in mm, for laser cutting or quotations). *Mirror* flips the layout left–right for face-down mounting.

## Recipes

- **Substrate prep**: the substrate design, sonication steps with times, and the surface treatment (N<sub>2</sub> dry first, then UV-ozone or O<sub>2</sub> plasma); the key facts list both in order, one step per line. Drag a step by its handle (⋮⋮) to change the order; with the handle selected, the arrow keys move it too.
- **Solutions**: for a perovskite, pick the A-site, B-site (Pb, Sn, Ge) and X-site ions with the chips, then type each fraction directly into the subscripts of the formula (Cs<sub>0.05</sub>FA<sub>0.80</sub>MA<sub>0.15</sub>…, FA(Pb<sub>0.5</sub>Sn<sub>0.5</sub>)I<sub>3</sub>). A site with one ion needs no number. A new solution starts as FAPbI<sub>3</sub>. With a mixed B-site, each halide is shared among the B-site salts by their fractions, and the molarity counts the B-site metals together. **Structure** switches between 3D and layered perovskites, general form RA<sub>n−1</sub>Pb<sub>n</sub>X<sub>3n+1</sub> (R = large organic spacer): **Ruddlesden–Popper**, (L)<sub>2</sub>A<sub>n−1</sub>Pb<sub>n</sub>X<sub>3n+1</sub>, two monovalent spacers (PEA, BA, OA, BzA, EA, DMA, ThMA); **Dion–Jacobson**, (L)A<sub>n−1</sub>Pb<sub>n</sub>X<sub>3n+1</sub>, one divalent spacer (PDA, BDA, EDA, 3AMP, 4AMP). Pick the spacer, then type the spacer and A-cation amounts in the formula (for example BA 2 and MA 3, or BA 0.4 and MA 0.6, which is the same ratio): their ratio sets n (RP n = 1 + 2·A/spacer, DJ n = 1 + A/spacer), and Pb and the halide follow. You can also type Pb directly. **Write with 2 BA** (or 1 for DJ) rewrites the formula in the usual form; the masses do not change. In terms of n: n = 1 is pure 2D, 2–4 quasi-2D, 5 and more often called quasi-3D, n → ∞ is 3D; non-integer values give a nominal ⟨n⟩. Per Pb the solution holds 2/n LX (RP) or 1/n LX<sub>2</sub> (DJ), (n−1)/n AX and one PbX<sub>2</sub>; molarity is mol Pb per litre, as for 3D. Notes appear for mixed halides (2D halide degradation) and for n ≥ 5 (splitting into lower-n phases in humid air). For a 2D passivation layer on a 3D film (spacer salt in IPA, for example), use the Custom solution type. Below the formula, each site's sum is checked; **Make it 1** scales the fractions so they add up to 1. The app allocates halides to PbX<sub>2</sub> first and gives the mass of each salt for the chosen molarity and volume. **All in one vial** or **Separate stock solutions**: with stocks, each salt is dissolved on its own in the solvent mixture (concentration and volume to prepare per salt; by default all stocks at M × total salt per Pb, so they add up exactly to the final volume), then the output lists the mass for each stock, the volume of each stock to pipette, the solvent to make up the volume and the additives for the mixed solution. **Volume of solvent**: the salts are dissolved in that volume of solvent (mol Pb per L of solvent). **Density method**: the volume is the final solution; the dissolved perovskite takes up its mass ÷ density (default 4.1 g/cm³, editable), so the solvent volume is reduced by that amount. The salt masses are the same in both. Under each salt is the container the mass is for: its purity sets the mass. With more than one container of that salt in stock, people with the **Inventory** tag pick another there, and every recipe then uses it. **Not in stock** means the mass assumes 100 % purity; **Not in the inventory** means the lab has no such substance yet, so there is no mass. ETL, HTL and custom solutions use mg/mL or mM. Additives can be given in mol%, wt%, mg/mL, µL/mL or µL of a stock solution per mL. Stirring, heating and cool-down are recorded.
- **Spin coating**: controller steps as time : rpm (time to reach the speed), dispenses before the spin or at *s remaining* (choose **Solution** or **Solvent** first, then one from that list), the 0.22 µm filter, annealing and activation steps. While editing, the spin curve above the steps shows the ramps, speeds, N<sub>2</sub> steps and when each dispense happens.
- **Organic evaporation**: material, thickness, rate (Å/s or Å/min), expected temperature and pressure (value × 10<sup>exp</sup> mbar), estimated time. Known materials (C60, BCP, BPhen, TPBi, NPB, TAPC) are shown as a 3D ball-and-stick model; drag it to rotate. Other materials show their name.
- **Metal evaporation**: substrate design and a mask drawn for it, metal, rate stages (Å/s until a thickness), controller thickness in kÅ and starting power. The output shows the scrape zone on the ITO, then the metal pattern over it.

## Stacks

**New stack** opens a wizard: choose **p-i-n** or **n-i-p** (the template sets the layer list; layers can be inserted or removed later), then one step per layer. For each layer pick the method and a preset card, or create a new preset without leaving the wizard. Spin and manual layers take a thickness for the 3D view. Tick **Change layer preview style** to set a layer's colour, opacity, roughness and metallic in the 3D view (for the substrate step: the glass and the ITO); **Default** goes back to the standard look, and unticking resets it. The Schematic view uses only the colour and opacity. **Previous**, **+ New layer** (adds an empty layer after the current one) and **Next** stay at the bottom of the screen while you scroll. **Review** lists all layers with **Edit**, **Insert above** and **Remove**. A metal recipe whose mask was drawn for a different substrate cannot be chosen. On a spin-coated layer whose solution is not a perovskite (a SAM, a transport layer), the solute's structure is drawn under the solution when its substance has a SMILES; run sheets never show structures.

The 3D view is built from the substrate and mask designs. The ITO is drawn as a thin coloured film on the glass, so the first layer is a flat slab; the metal follows the surface, so the counter electrode sits on the exposed ITO in the scrape zone with the same thickness as the rest of the metal; as soon as the view is exploded at all, it rises to the level of the other metal. Glass and ITO share one label; the leader line of the metal points to the nearest metal part. Heights are schematic: glass 1 mm, 100 nm of film = 0.1 mm. On a batch page the view settings (look, exploded, legend, flip, export) open from the cog in the bottom-left corner, as a bar along the bottom of the view; the stack moves up so the bar never covers it. With **Lines**, each line meets its layer at the edge nearest the labels, so layers cut away in the scrape zone and the metal strips are met where they really are.

- Drag to rotate (around the centre, from top view to side view).
- Scroll, pinch or use the slider to separate the layers (exploded view).
- **Realistic / Schematic** switches the look; **Export PNG** saves an image.
- **Legend** shows or hides the layer names; **Tags** puts them in rounded labels, **Lines** draws a line from each layer to its underlined name.

From an open stack, under the 3D view: **Print run sheet**, and **Start batch**, which asks only for the batch's name. Names tell batches apart: two batches cannot share one (a batch in the trash keeps its name until the trash is emptied). There are no batch codes.

## Batches

A batch freezes the stack, its recipes and the substances (with the container each recipe used and its purity) at the moment it is started. Editing a recipe later does not change the batch. Its name is the title of its page; click it to rename the batch.

- **Status**: Planned, Running, Done. Your running batch appears as a chip in the top bar; click it to return to the batch.
- **Layers**: each layer shows where it stands in the Calendar: **Not scheduled**, **Booked** (date and time), **Concluded** (date) or postponed. There is nothing to tick: the outcome you give a booked step is the record.
- **Run data missing**: concluded steps whose recipes have no run data under this batch yet are listed at the top, each with **Add run data**.
- **Add run data** next to each recipe opens the run data form with the batch chosen.
- **Variants**: the devices of the batch that differ from the default device (the stack the batch was started from). **Add variant**, name it, enter its substrates, then either choose **Another stack** (a premade variation; versions of the batch's stack are listed first) or list what changes from the default device: **Use another recipe** for a layer (versions of the layer's recipe first), **Add an additive**, **Add a layer**, **Leave out a layer** or **Describe another change**. A variant needs one of the two. Its recipes are frozen when saved, like the batch's own. The substrates of the default device and of each variant can be typed straight in the list. Removing a variant asks first: its frozen recipes go, and samples linked to it count as the default device. The print sheet, the report and the spreadsheet list the variants and their recipes.
- **Locked batches**: 14 days after a batch is Done it locks by itself. Its layers, run data, variants, notes, bookings and name stay as recorded (the page says so); comments, sharing and measurement links stay open. The batch page shows the date it will lock. An admin can **Unlock for 7 days** (it locks again by itself, or with **Lock now**); unlocking is written to the activity log. The batch list marks locked batches with a padlock.
- **Batch notes**: anything that applies to the whole batch.
- **From the inventory**: what the batch takes from the containers. While it is Planned, the amounts its recipes plan (each solution as prepared, solvents dispensed straight from the bottle in spin programs) and the container each comes from: the one used in recipes when the batch was started. Where the batch's run data give what was really weighed or dispensed (a salt weighed, a solvent volume added, a dispense volume, the substrates coated), that amount counts instead of the planned one, marked **From run data**. When it starts running (its first booking begins, or it is set to Running or Done), those amounts are taken from those containers: their **Left** goes down, and each container lists under **Taken by** what took from it. A container that is empty by then is replaced by the substance's container used in recipes; a substance with none in stock, or an amount that cannot be converted to the container's unit (mass to volume needs the substance's density), is listed as not taken. Moving the batch to the trash, or back to Planned, puts the amounts back; restoring it takes them again. Entering, changing or deleting run data afterwards takes the new amounts from the same containers (several entries for one recipe: the latest value of each field counts). Batches started before 0.45 took nothing. Without run data the amounts are the planned ones: correct a container's **Left** by hand after weighing it if needed.
- **Run data** lists every entry recorded for this batch, whether entered from the batch page or from a recipe page.
- **Print run sheet** (under the 3D view, left of **Schedule equipment**; the same button as on a stack) prints the batch on blank paper, with empty fields to fill in by hand at the bench. The text is a size larger than on screen, to read at the bench; a long layer continues on the next page, but no table or list is split.
- **Report (PDF)** prints a full report of the batch (save it as PDF in the print dialog): stack and layer order, every recipe with its values, the state of each layer from the calendar, batch notes, all run data, and the J–V results of the measurements linked to the batch (table per group, champion device, box plots). **Spreadsheet** downloads the same as an .xlsx file with one sheet each for the batch, layers, recipes, run data, J–V pixels and statistics.

## J–V curves

**J–V curves** (sidebar, under Measurements) reads the files the lab's J–V systems save and keeps the curves with the samples they belong to.

- **Import measurements**: drop the folder the system saved (or a .zip of it), or choose files. Supported: multi-pixel systems that save CSV files (such as Ossila's: "… J-V Data.csv", "… Metrics.csv" and the Settings folder) and systems that save one text file per curve ("…-JV-Backward-Sun-A1.txt" with "…-Parameters.txt"). Sample, substrate, scan and pixel are read from the file names; area and light intensity from the files.
- Before saving, link each sample to a **batch** or **stack** of the app (a batch with variants lists each variant too: "B-12, variant 5 % MACl"; statistics and comparisons keep variants apart, and What changed reads the variant's recipes), and under **Devices for the plots and device groups** choose which devices (substrates) go into the plots and give them a **device group** to compare modifications (for example "control" and "+ PEAI"). Devices without a group are grouped by their batch or stack. Both can be changed later in the measurement (same section above each sample's cells).
- **Cells**: with a linked batch or stack whose mask has the same number of pixels, every substrate is drawn as in the metal-evaporation recipe (glass, ITO, scrape zone, metal); otherwise the pixels are plain rounded boxes (P1, P2… or A1, A2…). Each pixel shows its number and PCE (darker blue = higher); **black** = dead (no current), **red** = short (current but almost no voltage; a pixel that shorts in one direction and works in the other is a shorted pixel, out of statistics). With **Both**, each pixel shows backward / forward PCE on one line under its number. A **golden border** marks the best pixel of each substrate and the best device (substrate) of each sample. Click a pixel for its J–V figure in journal style (7 × 5, closed frame, V 0–1.2 V by 0.2, J 0–30 mA/cm² by 5; forward solid and backward dashed in the same colour; the device's layer order with p-i-n or n-i-p; the scan with the pixel's best PCE marked ★ with PCE, FF, Voc, Jsc and Vmpp). **Lab logo** adds the lab's logo (set by an admin; plots never carry the lab's name); **Export PNG** (3×, white background) or **Export SVG** for papers and slides. Below the figure: the numbers for every scan, the hysteresis index and the values the instrument software reported.
- **Statistics**: journal-style box plots, one card per parameter. Pick which to show with the chips (J<sub>SC</sub>, FF, V<sub>OC</sub>, PCE, R<sub>s</sub>, R<sub>sh</sub>; R<sub>sh</sub> uses a log axis); each axis is fitted around the data so the boxes sit in the middle, and each plot exports on its own (**PNG**, **SVG** under it); **Export** gives all shown plots as one image, each plot as its own file, or every counted pixel as CSV. With **Lab logo** on, the logo sits in the same place on every plot: the bottom centre, or the top centre or a corner when data would be under it on any of them (a plot gets its own place only when no place is free on all). Each group (device group, batch or stack) has its own colour: backward box in that colour, forward box a lighter shade joined to it (**Both**), and the pixels as dots in a darker shade (gold ring = best; triangles = outliers beyond 1.5 × IQR). Untick **Show outliers** when one far-off value squeezes the boxes: the axis then fits the boxes and whiskers, and the points beyond it become an arrow at the top or bottom edge with their number (they still count in the box and the table; exported figures keep the arrows; the choice is remembered and also used by the batch report, comparisons and slides). **Density curve** adds the density of the dots beside each box (in the darker shade). Hover a dot or box for its values. Also a table with mean ± SD, median and best, and the champion device; the CSV (in **Export**) opens in Origin or LabPlot. On the J–V curves page, choose which measurements to include; inside a measurement, only that one.
- **Both** (Cells): every pixel shows its backward PCE above its forward PCE; the colour follows the better one.
- What counts in the statistics: working pixels only, never check sweeps, and when a pixel was measured more than once, its **best** scan (highest PCE) in each direction. The pixel map, the best pixel and device, the box plots, the Overview, records and comparisons all follow the same rule. Change it per curve in the pixel's table (Auto / Include / Exclude).
- **Check sweeps**: a quick exploratory scan run before the real measurement of the same pixel (for example 0.05 V steps, forward only, then the real one at 0.02 V with both directions). The app recognises it from the voltage step and the scan directions, not from the scan number: a scan is a check sweep when another scan of the same pixel is clearly finer, or as fine and with both directions. It is shown greyed with a **check sweep** label (scan selector and the pixel's table) and never counts; choose **Include** in the pixel's table if it really should. A pixel measured only once is never a check sweep. Existing measurements were checked when updating to 0.30.
- The numbers are calculated by the app from the curves (they match the instrument software on working pixels): Jsc at 0 V, Voc where the current crosses zero, maximum power on a fine grid, FF, PCE from the light intensity, Rs and Rsh from the slopes at Voc and at 0 V. Isolated glitch points (contact spikes) are ignored and counted in the pixel's table.
- A batch page lists the measurements linked to it, with the same cells, and can import directly for that batch.

## Comments and notifications

- Every stack, recipe, design and batch has **Comments** (a tab on presets, a section at the bottom of a batch). Write a comment, **Reply** to one, react with 👍 ❤️ 🎉 😮 🤔, edit or delete your own. Ctrl + Enter sends.
- **Mention someone** with **@**: type @ and the first letters of a name or username, then pick the person (arrow keys and Enter, or click). Only people who can open the item are offered. The mention shows as their name, and they are notified (instead of the usual comment notice). Adding a mention by editing a comment notifies the person added.
- The bell (top right) shows a red count of unread notifications. You are notified when:
  - someone breaks the **lab record** (best PCE ever on one of the J–V systems; everyone is told);
  - someone makes a new protocol **based on yours** (a new version or a duplicate of your preset);
  - someone **comments** on your stack, recipe or batch, or **replies** to your comment;
  - someone **mentions** you with @ in a comment.
- Click a notification to open what it is about; **Mark all as read** clears the count.

## Overview

**Overview** (top of the side menu) shows a **Week** or a **Month**; ‹ › move between periods. Everyone has an overview of their own work. The picker next to Week and Month changes whose it is: **Mine**; **My students**, for anyone named as supervisor or co-supervisor on a student's account; and, with the **Lab overview** permission (or as an admin), **The lab** and any person.

- **Summary**: the period in one sentence, a new lab record if there was one, three numbers (best cell, typical cell = median, batches), postponed or canceled steps if any, efficiency over time (hover for values, or **Show numbers**) and who was active. **Details** at the bottom opens the best cells, the batches started or finished, and the measurements.
- **People** (the lab or your students): a card per person with what they did in the period. Open a person for their page: best cell so far, progress measurement by measurement, recent batches and measurements; equipment time and setbacks are folded below.
- **Equipment**: booked hours per equipment and how busy it was (share of weekday working hours, 08:00–18:00), with who booked it.

**Export for a presentation** (Summary) shows a preview of a 16:9 slide with efficiency over time, the J–V curve of the period's best cell and the box plots (Jsc, FF, Voc, PCE) of that cell's batch, with the lab logo. Download the full slide, or each figure on its own to build your own slide, as PNG (PowerPoint, Google Slides) or SVG (sharp at any size, editable). The highlights slide (record, batches, best cells in words) is there too. People and Equipment have **Export slide** for their own 16:9 slide. A cell counts with its best working pixel.

## Comparing pixels

On a measurement's Cells tab, **Shift-click** pixels on any substrate or sample to compare them; each picked pixel gets a coloured outline. The comparison above the cells shows one J–V figure per pixel side by side (best scan; forward solid, backward dashed; or one direction); tick **All on one plot** to overlay them in one figure, one colour per pixel. It lists their numbers and exports as PNG or SVG (side-by-side figures export as one image). Shift-click a pixel again, or **Remove**, to drop it; **Clear** empties the comparison.

## Comparisons

**Comparisons** (sidebar, under Measurements) puts devices from any measurements side by side, so modifications measured on different days, or imported separately, can be compared. Each comparison is **private** until you switch it to **Shared**; others can then read it (and **Make a copy**) but not change it.

- **Add devices** opens the list of every device you can see (sample and substrate of each measurement), with its batch, measurement, best PCE and counted pixels. Filter by text, measurement, person or dates, tick the devices and **Add**.
- **Groups by name** (the default in Add devices) reads names as `batch_mod`: the part after the first underscore is the modification, so B1_control and B1_additive_annealed make two groups; "ref", "control" or "standard" becomes the reference. Names to check are listed: a name without an underscore, or one a letter or two away from a more common one (a likely typo that made a group of its own). Or put the devices straight into a group you choose.
- In the **Groups** list: rename a group, **Set as reference**, reorder, remove, or open the device list (names that differ from most of the group are marked).
- Results: **box plots** of the parameters you choose (PCE, V<sub>OC</sub>, J<sub>SC</sub>, FF, R<sub>S</sub>, R<sub>SH</sub>; the choice is saved with the comparison; R<sub>SH</sub> on a log axis; backward, forward or both; **Show outliers**, **Density curve**), the **J–V curve** of each group's best pixel, and the **parameters** table: devices, pixels and the median ± standard deviation of each chosen parameter per group, and the change in median PCE against the reference. Each box plot has its own PNG and SVG.
- **Relative to reference** divides every value by the median of the reference group in the same measurement and direction, so differences between measurement days cancel out; devices without a reference in their measurement are left out (and counted).
- **What changed** compares the recipes of the groups' batches (from each batch's frozen snapshot) with the reference: method, recipe and each recipe value per layer. A value that differs between a group's own batches shows as varying. Devices in the same batch as the reference have the same recipes, so only the sample names tell them apart.
- **Export**: a 16:9 slide (box plots, J–V curves and the parameters table); the box plots all in one image or each plot as its own file; the J–V curves all in one plot or one file per group (PNG or SVG); and an Excel file with the groups, every counted pixel and what changed.
- A comparison keeps references to the devices, not copies: when a pixel is excluded in its measurement, it is left out here too. Deleting moves it to the Trash.

## Lifetime runs

**Lifetime** (sidebar, under Measurements) lists the lifetime runs; **J–V curves** lists the other measurements. Both import the same way, and each import lands in its list. The lifetime test of multi-pixel CSV systems (such as Ossila's) scans the chosen pixels again and again, holding them at maximum power (or a set voltage) in between. Import the run's folder (or a .zip of it) like any measurement: the app finds the J–V Data and Settings folders, uses the copy of the run whose files match (an aborted first attempt leaves header-only files), and shows the run before saving: readings, pixels, length, pixel area, intensity and the best first reading. The files do not name the device, so give the sample and substrate as in your other measurements, or link it to a batch. Light and temperature readings are kept only when those sensors were connected. Points the instrument missed (a current of exactly 0) are left out.

The first reading counts in the statistics like any measurement; the later ones are the ageing and stay out of them. The **Lifetime** tab plots PCE, Voc, Jsc, FF, Rs or Rsh of every pixel against time (backward, forward or both scans), normalised to the first reading or in absolute values, with T90 and T80 lines; the table gives the first and latest values, the ratio, T90 and T80. Below, one pixel's J–V curves over the run, light (first) to dark (last). Export the figures as PNG or SVG and every reading as CSV (with the instrument software's own PCE for comparison).

Readings whose J–V curve crosses zero twice (the current reverses and recovers before Voc, often in forward scans of a degrading cell) are drawn as hollow points and left out of T90, T80 and the latest value: the app reads such a curve up to its first crossing and the instrument software to its last, so their values can differ a lot. An FF above 100 % means the current near Voc rose above Jsc during the scan, a transient after the hold at maximum power.

## Comments and reactions

React to a comment with any emoji: **+** under the comment opens the emoji keyboard (search, categories, skin tones). Click a reaction to add or remove yours.

## Calendar and batch scheduling

**Calendar** (side menu; on a phone, under Fabrication) shows the lab's equipment bookings by **Day** (one column per equipment), **Week** or **Month**. Each booking is a block in its equipment's colour with the experiment (batch and layer), the equipment, who booked it ("you" for your own) and the time; short bookings put them on one or two lines. A ✓ marks a concluded step, a ? a step waiting for its outcome; canceled and postponed steps are striped. Hours outside the lab's working hours (Lab setup) have red stripes, and empty days that are not working days are narrow. Booking there is allowed: the booking form says it is outside working hours, and the admins are told. **New booking** starts at the next working hour. Birthdays (day and month) show with a small cake in the day's header. When a block is too small or narrow to show everything, hover it: a card with all the details opens next to it. In the week and month views, click an equipment name (its colour is the bar under it) to show or hide it. Keys: ← → previous and next, T today, D W M the views.

**What a booking is for**: a booking is for one of your Planned or Running batches (and one of its steps), or for **No batch**, saying what it is for (a test run, maintenance); such bookings show their purpose in the calendar and ask no outcome. Equipment that can do **J–V measurement** (Lab › Equipment) measures finished devices: it takes one of your **Done** batches (even a locked one), or no batch with the reason it is booked. These bookings do not count as fabrication steps in the batch's progress, and ask no outcome.

**Schedule a batch** (on a computer): on the batch page, **Schedule equipment** (under the 3D view, on the right) opens the Calendar with a tray of the batch's equipment blocks under it. Steps that use the same equipment one after another are one block. Each block goes to equipment that can do its steps (what each equipment can do is set under Lab › Equipment, and a glovebox can do what the equipment inside it can); when several can, pick one in the block, and only equipment you are trained on is offered. Substrate preparation is two blocks when the recipe has a surface treatment: cleaning (sonication and N<sub>2</sub> dry), then UV-ozone or plasma. The run data of the substrate recipe is asked once, after the surface treatment. All solutions of the stack are prepared in one session, consecutive spin-coated layers share one session with their annealing, consecutive organic layers share one evaporation run, and the metal is its own block. **Anneal elsewhere** on a spin-coating block moves its annealing to a block of its own, on equipment that can anneal (a hotplate in another glovebox, say); **Anneal in the same place** joins them again. Each block lasts as long as its recipe says (substrate cleaning: the sonication and drying times; surface treatment: its own time; rounded up to 5 min), and at least the equipment's shortest booking. Drag each block onto its day and time in the week or day view; a dashed outline shows where it lands, red when the equipment is not free. Drag a booking to move it; drag its top or bottom edge to change when it starts or ends (a small bar shows the edges on hover). When every block is placed the batch page reads **Scheduled**. On a phone the Calendar is for looking and editing bookings, not for scheduling batches.

**Status follows the schedule**: a batch is Planned until its first booked step starts, then Running. When a booked step has ended, whoever booked it is asked how it went: **Concluded**, **Postponed** (to finish another time) or **Canceled**, with the reason for the last two. After **Concluded**, the run data of the step's recipes open one after the other (the solutions for the scale session, the spin programs for the spinner, the evaporation recipe for an evaporator), with every value required. If the notebook is not at hand, **Add it later**: the batch page lists the missing run data and you get a reminder. The question stays on screen until it is answered. The batch becomes **Done** when every step is answered and no postponed step is waiting for a new time (schedule it again from the batch page).

Single bookings can also be made in the Calendar: drag across empty time in the day or week view (a click books one hour), or **New booking**. Times snap to 15 minutes. A booking lasts at least the equipment's **shortest booking** (1 hour unless set otherwise under Lab › Equipment). Overlaps cannot be saved (admins can book anyway). Bookings start from now on: past time cannot be booked. To book equipment you need to be **trained** on it (see Equipment); time when equipment is **out of service** is drawn hatched and cannot be booked.

**Atmosphere**: when a step done in equipment that records its atmosphere (a glovebox) is concluded, its O<sub>2</sub> and H<sub>2</sub>O in ppm are asked too. Bookings outside a batch on such equipment ask only for the atmosphere.

**Cleanup after bookings**: equipment can have minutes of **cleanup** after each booking (set under Lab › Equipment; none unless set), drawn hatched under the block. The equipment stays taken during it, so the next person can only start after it: everyone has time to leave the glovebox clean without someone waiting. A new booking cannot start in someone's cleanup, nor end so late that its own cleanup runs into the next booking. The cleanup is per equipment: one glovebox's cleanup does not block another. Click a booking to change or remove it (**Undo** brings it back). **Drawings**: each equipment has a line drawing (balance, spin coater, small or thermal evaporator, UV-ozone cleaner, hotplate, glovebox, solar simulator, profilometer, ultrasonic bath or other), its working part in the equipment's colour. They head the Day view's columns, the booking form's equipment choice, the hover card and the Overview's equipment use. The drawing is chosen from what the equipment can do and its name, and can be changed under Lab › Equipment.

## Equipment

**Equipment** (side menu, under Lab) is the lab's equipment as it is: **places** (rooms), the equipment in each, and equipment that holds other equipment (a glovebox with a spin coater and a hotplate inside). Everyone can look; people with **Equipment management** (and admins) add places and equipment and reorder them (drag the handle; the Calendar's columns follow).

Open an equipment for its sheet:

- **What it can do**: the steps of the recipes it is used for (sonication, N<sub>2</sub> drying, UV-ozone, O<sub>2</sub> plasma, weighing, dissolving and stirring, spin coating, annealing, organic, metal or perovskite evaporation, J–V measurement, lifetime). A glovebox can stay empty here: it can do what is inside it.
- **Booking**: whether it is booked (equipment inside other equipment is booked with it, as a whole), its **shortest booking**, the minutes of **cleanup** after each booking, whether it **records its atmosphere** (O<sub>2</sub> and H<sub>2</sub>O asked when a step is concluded), and the drawing and colour.
- **Where it is**: **Move** it to another place or into other equipment; every move is kept with who moved it and when.
- **Responsible people**: they train others, edit and move it, and set it out of service. Being responsible counts as trained.
- **Trained**: who may book it. Admins need no training. People who had booked equipment before 0.38 were counted as trained on it.
- **Out of service**: periods when it cannot be booked, with a reason; people with bookings in that time are told.

Each person's **Details** (Admin settings › Users) also lists the equipment they are trained on, where people with **Equipment training** tick it.

## Inventory

**Inventory** (side menu, under Lab) has five tabs. Everyone can look; admins and people with the **Inventory** tag edit.

- **Storage**: each cabinet, desiccator, glovebox or fridge is a card drawn from the front, one line per division with a bar for how many containers sit there. **New storage** asks only for the name and the type. Open a card, then **Add division** to split it into shelves, trays, drawers or anything you name; each division is a line with its name, and clicking the name folds its containers away or shows them. Hover a division to add a container to it, rename it or remove it.
- **Containers**: every bottle with how much is left (and of what size), where it is, supplier, lot, purity, barcode, opened and expiry dates, and who added it and last changed it, and when. Filter by role and by control. Expired and soon-to-expire containers are marked. **Add container** asks for the substance first: pick one the lab has, or type a new name to make it. Several containers of one substance are normal (another purity, lot or supplier); tick **Used in recipes** on the one recipes take, usually the bottle in the glovebox. With none ticked, recipes take the newest one. **Mark empty** keeps a finished bottle in the history. **Import CSV** reads an export from OpenEnventory or any spreadsheet saved as CSV. It shows what it read before saving anything: each substance (a name you can shorten, its formula and molar mass, its roles, and whether the lab already has it, by CAS number or by name) and each place in the export with the storage place and division it goes to ("Cabinet 2 - 07" becomes storage place Cabinet 2, division 07; new ones are made). Comments saying the Federal Police or the Army controls a substance tick that box.
- **Consumption**: reagent use per week or per month from the recipes of running and done batches (each solution as prepared, plus solvents dispensed straight from the bottle in spin programs): what their run data say was weighed and dispensed, else the planned amounts. For each chemical: a small bar chart of the last 26 weeks or 12 months, this period, the average over the last 8 weeks or 6 months, the stock in containers that are not empty, and the date it runs out at the average rate (red within 30 days). **Unusual use** marks a week or month above twice the earlier average and well outside its normal spread. Click a chemical for the full chart and the batches behind it. Mass and volume are converted with the substance's density. Since 0.45 the stock also goes down by what each batch took (see **From the inventory** under Batches).
- **Substances**: what the containers are of, made from them: name, CAS number (its check digit is checked), formula, SMILES (the structure, drawn at the top of the substance's page in the style of a skeletal formula; copy it from ChemDraw with Edit › Copy As › SMILES; common organic compounds get one from their CAS number, and **Use … from the SMILES** fills in an empty formula), molar mass (worked out from the formula when it can be), density, melting and boiling points, refractive index, roles (salt, solvent, ETL, HTL, additive, organic, metal; several are fine, and they filter the lists in recipes), hazard pictograms, and whether the Federal Police or the Army controls it. Open one to edit it and to choose which of its containers recipes use. A substance with no containers left can be deleted.
- **Storage types** (Inventory tag): the options in the type picker. Add one with a name and an icon, rename it, click its icon to choose another, or remove it once no storage uses it.

## Profile and tags

**Edit profile** (in the menu under your photo, next to your name): photo (click the photo to choose a picture, then drag and zoom to crop), display name, default visibility of new presets (Shared unless you change it), theme, password and the phone invite.

Admins make tags in **Admin settings → Tags** (a new install has none): a list of tags; click one for its name, colour, what it gives and who has it, or **New tag**. A tag that gives nothing is a label that only describes people (Master's, PhD, Visitor, a research topic). A tag can give any of: **Private comments** (sees every preset, batch and measurement, can tick **Private, only for …** to comment only to the owner, and those comments come first, highlighted), **Lab overview** (the lab's overview and anyone's), **Inventory management** (edits the substances and the inventory), **Equipment management** (adds and arranges places and equipment) and **Equipment training** (records who is trained on which equipment).

Hold **Shift** while opening **Edit profile** to see the **Funny settings** (all off until you turn them on): a red eye next to search while the Professor is online, and breaking news from the lab's alternative universe in the top bar, one headline at a time with a pause between them (admins set the pause for everyone, 30 s by default). With both on, the news also covers the Professor while they are online, and opens at once with a red, shaking border when they arrive.

## Help

The **?** button next to the bell opens the quick start and this guide.

## Trash

Deleting a stack, recipe, design, batch or measurement moves it to the **Trash** (bottom of the side menu; on a phone, ☰ → Account). Right after deleting, **Undo** in the message at the bottom brings it back. From the Trash page you can **Restore** for 30 days, or **Delete for good**; after 30 days items are removed automatically. Admins see everyone's deleted items.

## Lists and conventions

- **Cards or List**: Recipes, Designs, Stacks, Batches, J–V curves, Lifetime and Comparisons can show cards or a list; the choice is one for the whole app.
- **Reordering**: everything with an order has a handle (six dots) to drag it, or focus the handle and use the arrow keys: substrate-prep steps, spin steps and dispenses, solvents and additives, stack layers (in the stack's Review step; the substrate stays at the bottom), comparison groups, inventory divisions and equipment.
- **Dates** are day/month/year (06/11/2026) and times 24 h, whatever the browser's language. A measurement day is shown as that day everywhere (before 0.34 some lists showed the day before).
- **Moving to the trash** asks nothing: the toast offers **Undo**, and Trash keeps it for 30 days. Only what cannot be undone asks first (removing equipment, deleting users or tags, emptying the trash).

## Links

Every page and item has its own address: a batch (`#/batches/12`), a measurement, a comparison, a recipe or design, a container. **Copy link** (in the item's header) copies it; anyone who can see the item opens it with the link, after signing in if needed. The browser's **Back** and **Forward** buttons move between what you opened, and a bookmark reopens the same item. The address uses the computer's address on the lab network, so links work for everyone on that network.

## Data package

A **data package** is one .zip for a data repository, made from the batches, measurements and comparisons you choose. Open it from a batch (**Export › Data package**), a measurement (**Data package**), a comparison (**Export › Data package**) or the Batches, J–V curves and Lifetime lists (**Data package**, starting with nothing chosen).

- **What goes in**: tick batches, measurements and comparisons (filter by name or person). With **Also add what they are linked to** on, a batch brings its measurements, a measurement its batches and a comparison its measurements; those are listed as "linked to a chosen item".
- **Describe it**: title, description, authors (separated by ;), affiliation, funding agency and grant number, licence (CC BY 4.0, CC0, CC BY-NC 4.0, or not decided yet) and keywords. Affiliation, funding, licence and keywords are remembered for the next package.
- **Inside the .zip**: a **README.md** that describes the data (who, when, what, the folder layout, units and methods: how the parameters are calculated and which pixels count), **metadata.json** with the fields a repository deposit asks for (in the form Dataverse repositories use), and **manifest-sha256.txt** with the SHA-256 of every file (check with `sha256sum -c manifest-sha256.txt`). Each batch has batch.json (the stack and recipes as frozen at the start, variants, bookings, run data) and the batch spreadsheet's tables as CSV; each measurement has measurement.json, pixels.csv (every curve with its parameters, check sweep or not, counted or not) and one CSV per curve (V in volts, J in mA/cm²); each comparison has comparison.json and pixels.csv.
- Files are CSV (UTF-8, comma-separated, decimal point) and JSON, readable without the app. Nothing leaves the computer: the package is made in the browser and downloaded.

## Run data

Run data are structured entries of what really happened: measured masses and volumes, powers, rates, pressures, thicknesses, with the recipe value next to each field, plus deviations and notes. Enter them from a batch (**Add run data**) or from a recipe's **Run data** tab; choose the batch so the entry is listed on the batch page.

Metal evaporation asks, per stage (each rate), for the power and the pressure reached at that rate, plus the sensor life as **T.V = XX.X %**, the final thickness and the base pressure. Pressures are typed as a value and an exponent (2.1 × 10⁻⁶ mbar); the exponent carries over from the previous field, so usually only the value is needed. A comma works as the decimal sign. The printed batch sheet has the same blanks.

## Search

**Ctrl K** (or the search box) finds presets, batches, measurements, comparisons, containers (by name, CAS or lot; opens the container) and chemicals, and jumps to any section. On a phone, use **Menu › Search**.

## Phones and tablets

The app works in a phone browser on the same network as the lab PC. Start the PC with **start-network** (start-network.bat on Windows, start-network.command on Mac, start-network.sh on Linux), then open the profile menu (your initial, top right) › **Invite a phone (QR code)** and scan the code with the phone camera; the link opens the app in the phone's browser. The start window also prints the address. University networks such as eduroam may keep devices from reaching each other; a lab router or a phone hotspot works. The bottom bar has **Fabrication** (stacks, batches, calendar), **Measurements**, **Recipes** (all recipe kinds) and the menu (☰) for designs, the inventory, search, help and your profile. Inside Fabrication and Recipes, the chips at the top switch between their sections, and each tab reopens the section you used last. Phones are best for ticking batch layers and entering run data; drawing designs is easier on a computer.

## Account

**Getting an account**: on the sign-in screen, **Request access**. Give your first name(s) and surname(s), choose which surname goes in your username (it shows as you type: every first name and the first letter of the surname, lower case, without accents, e.g. Ana Clara de Souza → **@anaclaras**; if that is taken, the next letter of the surname is added), your institutional email (the lab sets which domains are accepted), birth date, department, supervisor and co-supervisor if any, and a photo. The admins are notified. Signing in with your username while you wait says so; if a request is declined, you see the reason.

**First sign-in**: once an admin accepts, type your username, leave the password empty and **Continue**. Confirm the email and birth date you gave, then choose a password: at least 8 characters, with an upper case letter, a number and a special character (! @ # % & * ? …). Accented letters (ã, ç, é, Ã, Æ…) count as letters, typed any way. The same happens after an admin resets your password, and for visitors an admin added.

Click your photo or initial (top right) for **Edit profile** (photo, name, about you, settings, password), the theme (System, Light, Dark), the phone invite and the app version. **About you**: institutional email, birth date, department, supervisor and co-supervisor; untick **Show my birthday** to keep it (day and month) out of the calendar. Accounts from before 0.36 are asked once per session to add the email, birth date and department. After 5 wrong passwords in a row, signing in is blocked for 10 minutes.

## Live updates

The app shows changes made by others as they happen: a booking, a new batch, a comment, a measurement appear without reloading the page. A tab in the background catches up when you return to it.

## For admins

**Admin settings** (profile menu or Menu) has one tab per job:

- **Users**: each person with department, supervisors, age and email (click a person for their details and equipment training; **Edit details** to change them), reset passwords (the password stops working; the person chooses a new one at the next sign-in, confirming email and birth date), disable accounts, delete profiles; tags; **Add a visitor** (the only accounts admins make themselves: name, email, birth date, institution and the last day of the visit, after which the account cannot sign in). A deleted profile can no longer sign in and its username is free again; everything the person made stays, shown as “username (former)”. Their private items stay private (visible to admins and people with Private comments only). Passwords need at least 8 characters with an upper case letter, a number and a special character, and cannot be well-known passwords or contain the username.
- **Access requests**: who asked for access, with photo, email, department, supervisors and birth date. Pick the tags they get and **Accept**, or **Decline** with an optional reason (they see it when they try to sign in). The tab shows how many are waiting; admins are also notified.
- **Lab setup**: what the first setup asked. **The lab**: full name and acronym, and which of the two PANOPTICA shows (as PANOPTICA · name everywhere: sign-in screen, top bar, exports, run sheets); institution, the email domains that may ask for access, and the departments people choose from; plots carry the lab logo only, never the name. **Sign-in screen**: the picture on its left side (until there is one, a drawing of a panopticon); the lab logo, placed in a corner, the middle of an edge or the centre, with or without a white background; the institution's logo; and whether the foot of the panel shows the institution's name, its logo or both. A preview shows the result. The lab logo is also the one offered on exported figures. **Working days and hours**: per day of the week, weekends included.
- **Backups**: make a backup now, download backups. Each backup is opened and checked after it is made. **Second copy off this computer**: a folder on a network drive or kept in sync by Google Drive, OneDrive or Dropbox, where every backup is also copied, encrypted by default. **Show key** shows the key of the encrypted copies: save it somewhere safe.
- **Security**: a checklist of what keeps the data safe (encrypted connection, recent checked backup, encrypted second copy, intact activity log, number of admins, temporary passwords, unused accounts), each with what to do when it is not in order.
- **Activity log**: every change, sign-in and refused request, with who, when and from which address; search, filter by person, export as CSV. The content of changes is not stored. Each entry is linked to the one before, so an entry edited or removed in the database shows up as a broken log.
- **Updates**: the installed and the latest version, release notes, **Download** and **Install now**. Updates come from the GitHub repository (with its read-only token while it is private) and are free. The app downloads the package made for the modules its licence lists.
- **Licence**: the lab's licence from PANOPTICA: the lab it was issued to (its full name and acronym), its modules, and how many people it covers against how many have a working account now (requests waiting and ended visits do not count). At that number, accepting a request, adding a visitor and enabling an account are refused with a note to contact PANOPTICA to upgrade; everyone who has an account keeps working. **Install a new licence…** takes a file PANOPTICA sends (an upgrade, or a module added), and only on the computer that runs PANOPTICA; one that was changed, or made for another lab, is refused. Only the modules it lists start (a change of modules applies when PANOPTICA restarts). On an install made by PANOPTICA Setup the licence file is required: missing or not valid, Admin settings says so on every tab and no one new can be let in until it is installed again; lost it? PANOPTICA makes a copy. A manual install works without one. The licence is kept in the database, so a backup restored on another computer keeps it. The lab's names in the licence are PANOPTICA's record; the names the lab shows are its own (Lab setup).

**First setup**: a new install opens setup screens on the computer that runs PANOPTICA: your admin account, the lab, the sign-in screen and the working hours. Then you land in the app. An install made by PANOPTICA has a one-time setup code on its install sheet: with it, the setup can be done from any computer on the lab network (it asks for the code first). The code works once; without it, other computers say PANOPTICA is not set up yet.
